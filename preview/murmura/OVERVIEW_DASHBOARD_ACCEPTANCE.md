# 原 Dashboard 完整汇总整合到 Overview

2026-10-25。本轮只改隔离工作树与本机 3219 测试站；没有提交、推送、部署、正式数据库操作、Clerk 权限修改或 Slack 发送，没有启动助手。

## 已整合的五项

| 原 Dashboard | 新版位置及规则 | 同批本机样稿对照：旧 / 新 |
| --- | --- | --- |
| 今天要做的任务 | Overview 顶部“工作总览”；马来西亚当天截止，排除已完成和已归档。保留普通任务和内容发布任务 | 7 / 7 |
| 已经过期的任务 | 截止时间严格早于当前时间，仍未完成；今天到期但已过时间的任务可以同时出现于今天及过期卡片 | 4 / 4 |
| 等待上司检查 | 所有审核中的内容，包括设定时间已过但仍在审核的内容 | 2 / 2 |
| 最近准备发布 | 已经批准且发布时间晚于当前时间；未来草稿不算已批准待发 | 1 / 1 |
| 超过时间还没发布 | 发布时间已经到达或已过，但未发布；沿用原规则，包含草稿、审核中、需要修改和等待发布 | 3 / 3 |

新页面通过原来的 `taskRepository.list()` 与 `listScheduledContent()` 读取资料，没有建立另一套业务数据，也没有复制正式资料。现有内容进度、周日历、平台、文件库、站内通知和团队入口继续保留。

## 列表与入口

- 每类卡片显示完整数量，默认先显示五项；更多项目可直接展开，不会只显示数字而找不到剩余记录。
- 按截止／发布时间排序，较早的在前。同一条任务可符合今天及过期两个独立分类，不能把两张卡片的数量当成不重复总数相加。
- 每条任务打开原 `/tasks/[id]` 详情，使用已经接好的新版外框；内容打开 `/marketing/content/[id]`。
- 实际点击任务详情和等待审核内容详情均成功；内容详情仍有原审核进度、指定文字留言、普通留言、文件和历史区。没有在这轮改变审批或编辑权限。
- 空列表继续显示五类卡片及各自的明确提示。查询失败会交给现有错误处理，不会假装成零条资料。
- 同排卡片对齐、手机单列；桌面与深浅色检查完成。新卡片保留链接焦点样式；更多列表使用原生 details/summary，可键盘操作。
- 刷新或重新打开页面时重新计算当前汇总，与原 Dashboard 的服务端读取方式一致；本轮没有新增常驻自动刷新功能。

## 实际验收

- 本机临时数据库用应用原有 SQL 函数创建内容、提交审核及批准样稿；旧 `/dashboard` 与新版 `/marketing` 同时读取同一批临时资料，五类数量全部一致。`evidence/overview-dashboard-2026-10-25/count-comparison.json` 保留对照。
- 测试资料包括七条今天任务、一条昨天任务、已完成／已归档的排除样本、未来待审核、未来已批准、超时草稿、超时审核与已批准到时未发布内容。
- 样稿中的两位管理员是本机假资料，没有创建真人登录账号或修改真人 Clerk 权限；这不等同真人双人协作验收。
- 手机展开后确实可见全部七条今天任务；320px 与 390px 整页宽度无横向溢出。
- 1440px 桌面、浅色／深色已实际查看。由于应用窗口尺寸变化，部分直接截图实际为 527px 手机布局，未冒充桌面证据；桌面证据来自明确尺寸的同源测试视窗。
- 完整 Vitest：385/385，108 个文件。
- 最后的卡片高度调整后，相关统计、页面接入及导航映射测试：8/8。
- 全项目 TypeScript、本次相关 ESLint、`git diff --check` 通过。
- jsdom 链接测试的 `Not implemented: navigation to another Document` 提示保留；真实浏览器的任务与内容导航已另行点击。
