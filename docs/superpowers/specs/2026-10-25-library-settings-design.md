# 文件库与设置完善

依据：用户选择上一轮差异说明第 3、5 项并要求完善。沿用已有 Next.js、Clerk、Supabase、BlockNote 和 Arc Select，只在隔离环境实现；不发布、不改正式数据库，不启用外部社交平台功能。

## 文件库
- 保留上传、预览、下载、附件独立复制及归档恢复。
- 个人收藏、文件标签、标签筛选、最新/最常使用排序、实际被几篇当前内容使用的计数。
- 多选收藏和多选移除；员工只能修改自己的素材，管理员可管理全部；批量移除先检查全部权限，任何一项无权限则全部不改并提示。
- 文案模板、Hashtag 集、快捷回复：新增、编辑、软删除恢复、搜索、复制。员工编辑自己的资源，管理员管理全部，所有已验证成员可读。编辑使用版本检查避免覆盖同事修改。
- 草稿/需要修改的正文提供插入入口，通过当前协同编辑器插入，不直接改送审快照、不绕过同步或审批。复制/插入成功后才记录使用次数，重复请求不重复计数。
- 收藏、计数、资源集中读取，不能恢复成逐条取附件的慢查询。

## 设置
- 个人资料与账号安全使用 Clerk 正式账号管理界面，不能修改角色或放宽登录工作区限制。
- 管理员可保存工作区名称、说明和一周起始日；名称显示于页头，一周起点实际用于日历。员工仅查看。排期时区固定马来西亚。
- 主题选择提供浅色、深色、跟随系统，保存到当前浏览器。
- 保留真实 Slack 配置。审核规则保持员工双管理员、管理员现有自审/另审方式，展示实际管理员和当前规则，不新增绕过开关。
- 排期提供 JSON、CSV；管理员可导出列明范围的工作区资料备份。不得导出密钥、签名链接、私人消息或其他人的私人收藏；不提供清空资料按钮。
- 不加入收费功能。

## 实现选择
沿用现有数据库扩充元数据与资源表，读取和修改都走已验证身份及服务端动作。没有另造一套文件存储或登录系统。新迁移只在本机测试数据库验证，正式执行留待用户另行授权。

## 验收
权限、个人收藏隔离、标签验证、版本冲突、批量部分失败、资源插入和复制、使用次数去重、工作区保存后的页头/日历变化、CSV 公式保护、导出权限和范围。最后做完整测试、类型检查、构建及电脑/手机布局检查；真实双人并发和正式环境验收必须单独标示。
