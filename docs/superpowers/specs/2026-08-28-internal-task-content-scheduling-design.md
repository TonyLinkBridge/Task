# 内部任务与内容排期工具：设计规格

日期：2026-08-28  
状态：用户已于 2026-08-28 确认，可以进入开发计划

## 1. 这个工具要解决什么问题

这是一个给员工和两位上司使用的内部工具，主要用来：

- 建立、分派、跟进和完成内部任务；
- 准备未来要发布的内容；
- 安排内容的发布日期和时间；
- 让上司查看内容、留言和批准；
- 到发布时间时，在 Slack 频道提醒员工；
- 保存修改、留言、批准、提醒和发布记录。

第一版只提醒员工手动发布。系统不会直接连接 Facebook、Instagram 或其他平台自动发布。每个平台的自动发布方式不同，所以留到第二阶段逐个平台增加。

## 2. 使用者和权限

开始时有一位员工和两位上司。两位上司都是管理员。

### 员工可以做什么

- 建立和修改任务；
- 分派和拖动任务卡片；
- 建立和修改内容草稿；
- 上传图片、影片和文件；
- 把内容交给上司检查；
- 根据上司留言修改内容；
- 确认内容已经发布。

员工不能：

- 批准内容；
- 修改 Slack 通知设置；
- 管理发布平台；
- 进入管理员设置。

### 管理员可以做什么

管理员可以使用员工的全部功能，也可以：

- 批准内容；
- 留言并退回内容；
- 新增、修改和停用发布平台；
- 设置 Slack 通知和频道；
- 查看全部历史记录；
- 查看和重发失败的 Slack 通知。

用户权限在 Clerk 的 public metadata 里面手动管理。新用户第一次通过 Slack 验证后，默认是员工。

资料格式如下：

```json
{
  "role": "admin",
  "slackTeamId": "T094DTFCVA8",
  "slackVerifiedAt": "2026-08-27T06:18:15.954Z"
}
```

## 3. 使用什么技术

- Next.js：网站和页面；
- Vercel：运行网站；
- Base UI：按钮、弹窗、选择器等界面；
- Square UI Base UI Tasks 模板：任务页面的起点；
- BlockNote：编写主要内容；
- Liveblocks：让 BlockNote 内容和指定文字留言即时同步；
- Clerk：账号、Slack 登录和用户权限；
- Supabase Database：保存任务、内容、留言和记录；
- Supabase Storage：保存图片、影片和文件；
- Supabase Cron：定时检查哪些内容到了发布时间；
- Supabase Edge Function：发送 Slack 消息；
- Slack App：Slack 登录验证和频道通知。

登录只使用 Clerk，不使用 Supabase Auth，避免同一个人有两套账号。

BlockNote 第一版加入多人即时同步和指定文字留言，但不使用 AI、PDF/Word 导出和多栏排版等 XL 功能。

Supabase 仍然是主要后台，负责账号对应资料、任务、排期、一般留言、指定文字留言资料、审核版本和历史记录。Liveblocks 只负责 BlockNote 文件的即时同步，让多人看到相同内容，并让指定文字留言的位置跟着文字变化。每次提交审核时，系统会把当时的完整内容版本保存到 Supabase，批准记录必须对应这个固定版本。

## 4. 登录方式

登录体验参考线上 JUYU Help Centre 的整体做法：

1. 没登录的人打开内部页面时，自动去登录页；
2. 系统记住他原本要打开哪个页面；
3. 登录页清楚显示指定的 Slack Workspace；
4. 用户点击“使用 Slack 继续”；
5. Clerk 处理 Slack 登录；
6. 只有第一次注册时，系统检查 Slack Workspace ID；
7. 通过后，系统把 `role`、`slackTeamId` 和 `slackVerifiedAt` 写入 Clerk；
8. 新账号默认是 `employee`；
9. 登录完成后回到原本的页面。

以后登录不再重复检查 Slack Workspace。

如果员工离职，管理员需要在 Clerk 手动停用或删除他的账号。

其他 Slack Workspace 的账号不能完成第一次注册。

系统后台每次都会检查 Clerk 身份和权限，不能只靠隐藏画面上的按钮。

## 5. 系统里面有哪些页面

### 首页

首页显示：

- 今天要做的任务；
- 还没完成和已经过期的任务；
- 等待上司检查的内容；
- 最近准备发布的内容；
- 已经过了发布时间但还没确认发布的内容。

### 任务页面

任务使用 Kanban 看板，分成：

- 还没开始；
- 正在做；
- 等人检查；
- 已经完成。

每张任务卡显示标题、负责人、完成日期、优先级和留言数量。用户可以直接拖动任务卡。

### 内容排期页面

相同的内容可以用三种方式查看：

- 日历：看哪一天要发布什么；
- 列表：方便搜索和筛选；
- 看板：按内容目前的进度排列和拖动。

可以按照发布平台、负责人和审核情况筛选。

看板上的拖动只用于正常推进工作，不能跳过审核。例如，员工不能把“等待审核”的内容直接拖到“已批准”。系统后台仍会检查所需批准是否齐全。

### 内容详情页面

一条内容包含：

- 内容标题；
- BlockNote 主要内容；
- 图片、影片和文件；
- 一个或多个自定义发布平台；
- 发布日期和时间；
- 负责员工；
- 目前状态；
- 上司批准记录；
- 编辑器下面的普通留言区；
- 文章里面的指定文字留言；
- 修改记录；
- 发布确认记录。

整个系统统一使用马来西亚时间 `Asia/Kuala_Lumpur`。用户只看到简单的日期和时间，不需要选择时区。

第一版不加入这些额外资料：

- 内容目的；
- 目标观众；
- 行动按钮或链接；
- 标签和内容分类；
- 每个平台不同的文案；
- Hashtag；
- 图片说明文字。

### 管理员设置

只有管理员可以：

- 新增、修改和停用发布平台；
- 选择 Slack 通知频道；
- 开启或关闭每一种 Slack 通知；
- 设置提前多久提醒；
- 查看系统成员；
- 查看 Slack 是否发送成功；
- 重新发送失败的 Slack 通知。

管理员可以选择指定 Slack Workspace 里面、Slack App 有权发送消息的频道。如果是私人频道，需要先把 Slack App 加进该频道。

## 6. BlockNote 怎样使用

BlockNote 只负责主要内容。员工可以写段落、标题、清单、表格和链接，也可以放图片、影片、声音和文件。

发布平台、发布时间、负责人、批准情况和发布状态放在固定栏目，不放进 BlockNote。这样系统才能正确筛选、提醒和检查。

第一阶段同时提供两种留言：

1. 编辑器下面的普通聊天留言，用来谈整篇内容；
2. BlockNote 的指定文字留言，用来选中某一段文字后直接提出意见。

指定文字留言可以回复、标记为已经解决，也可以重新打开。每一条都显示留言人和时间。员工和管理员都可以留言与回复，但不能冒充别人、修改别人的留言或删除历史记录。

BlockNote 的指定文字留言需要 Yjs 多人即时同步。第一阶段使用 Liveblocks 负责同步，并使用 BlockNote 提供的安全留言方式，把留言操作交给系统后台检查。系统后台会通过 Clerk 确认身份和权限，再把留言资料保存到 Supabase；不能只靠画面上的按钮控制权限。

参考：[BlockNote 留言功能说明](https://www.blocknotejs.org/docs/features/collaboration/comments)和[BlockNote 多人即时编辑说明](https://www.blocknotejs.org/docs/features/collaboration)。

草稿会自动保存。

## 7. 内容怎样审核

内容状态是：

1. 草稿；
2. 等待审核；
3. 需要修改；
4. 已批准和已排期；
5. 等待发布；
6. 已发布；
7. 已收起。

### 员工建立的内容

1. 员工建立和修改草稿；
2. 员工点击“交给上司检查”；
3. 主要内容暂时不能继续修改，但员工和上司仍然可以留言与回复；
4. 两位不同的管理员都必须批准；
5. 只有一人批准时，显示“已批准 1/2”；
6. 管理员可以留言并要求修改；
7. 退回后，员工可以继续修改；
8. 员工修改后重新提交；
9. 重新提交时，之前的批准全部取消；
10. 两位管理员都批准后，内容进入排期。

### 管理员建立的内容

建立内容的管理员可以选择：

- 自己直接批准；或
- 交给另一位管理员检查。

管理员建立的内容只需要一次批准。如果选择交给另一位管理员，就必须等对方批准。

### 已批准的内容再次修改

如果已批准的内容又被修改，旧的批准会取消，内容重新进入相应的审核流程。

## 8. 自动建立发布任务

建立排期内容时，系统自动为负责员工建立一个发布任务。

任务名称类似“发布 XXX 内容”，完成时间与内容发布时间相同。

员工点击“已发布”后：

- 系统记录由谁发布；
- 系统记录实际发布时间；
- 对应的发布任务自动变成已完成；
- 系统加入一条发布历史；
- 如果管理员有开启通知，Slack 会发送完成消息。

## 9. Slack 通知

管理员可以分别开启或关闭这些通知：

- 员工提交内容；
- 第一位管理员批准；
- 所有需要的批准已经完成；
- 管理员留言并要求修改；
- 员工修改后重新提交；
- 提前发布提醒；
- 到达发布时间；
- 员工确认已经发布。

Slack 消息包括内容标题、目前状态、负责员工、相关留言摘要和返回系统的链接。

到达发布时间时：

- 已经批准的内容会在 Slack 提醒员工发布；
- 还没批准的内容不会叫员工发布；
- 系统会显示“还没批准”，并在 Slack 提醒管理员处理。

如果发布时间被修改，旧时间的提醒会取消，系统改用新时间。

如果 Slack 发送失败：

- 系统保存失败记录；
- 管理员可以重新发送；
- 重新发送成功也会留下记录；
- 系统要避免同一条成功消息重复发送。

## 10. 文件怎样保存和保护

文件直接上传到 Supabase Storage 的私人空间。

每个文件记录：

- 文件名称；
- 文件类型；
- 文件大小；
- 谁上传；
- 上传时间；
- 属于哪一条内容。

用户打开文件前，系统先检查 Clerk 登录和权限，然后才产生一个短时间有效的文件链接。系统不会使用长期公开链接。

Supabase 管理员密钥只放在系统后台，不会发送到浏览器。

## 11. 修改和操作记录

系统会记录：

- 谁建立资料；
- 谁修改内容；
- 内容状态怎样改变；
- 谁留言；
- 谁批准；
- 谁退回内容；
- 谁修改发布时间；
- Slack 是否发送成功；
- 谁确认已经发布；
- 谁把资料收起来。

每一条记录都有操作者和时间。

平时不会直接永久删除任务和内容，而是先“收起来”。批准和历史记录不能随便删除。管理员可以查看全部记录。

## 12. Supabase 里面保存哪些资料

Supabase 会分别保存：

- 从 Clerk 同步过来的用户资料；
- 任务；
- 任务留言；
- 内容；
- 自定义发布平台；
- 上传文件；
- 批准记录；
- 审核留言；
- 指定文字留言和回复；
- BlockNote 即时同步文件的对应编号；
- 修改和操作历史；
- Slack 设置；
- Slack 发送记录。

Clerk 仍然是账号和当前权限的标准。Supabase 保存系统功能需要的用户资料，以及任务、留言和历史记录使用的名字与编号。

## 13. 出错时怎样处理

- 草稿自动保存失败时，画面会提醒用户，尚未保存的内容不会马上消失；
- 文件上传失败时，会显示哪一个文件失败，并允许重试；
- 批准结果和批准历史一起保存，避免两边资料不同；
- 每次 Slack 提醒都有自己的发送记录，避免重复发送；
- 失败的 Slack 消息可以安全重试；
- 如果内容已经被别人修改，旧页面不能批准旧版本；
- 即时连接中断时，画面会清楚显示尚未同步，并在恢复连接后继续同步；
- 指定文字留言的新增、回复、解决和重新打开都要经过后台权限检查；
- 没有权限的人即使自己调用系统后台，也会被拒绝；
- 修改发布时间后，旧提醒不会继续发送。

## 14. 第一版完成时要通过的检查

- 指定 Slack Workspace 的成员可以第一次注册；
- 其他 Workspace 的 Slack 账号不能注册；
- 已经完成第一次 Workspace 验证的用户，以后登录不需要再次验证 Workspace；
- 新账号默认是员工；
- 在 Clerk 改成管理员后，重新刷新 Clerk 登录资料便获得管理员功能；
- 员工可以建立、分派、留言和拖动任务；
- 建立排期内容后，系统自动建立发布任务；
- BlockNote 草稿可以自动保存和重新打开；
- 上司可以选中一段文字留言，员工可以看到并回复；
- 指定文字留言可以标记为已经解决和重新打开；
- 两个人同时打开内容时，可以看到最新内容和留言；
- 图片、影片和文件可以上传，只有有权限的人可以打开；
- 员工提交内容后不能继续修改；
- 员工内容必须由两位不同管理员批准；
- 管理员内容可以自己批准，或者交给另一位管理员批准；
- 管理员要求修改后，员工可以继续编辑；
- 重新提交时，旧批准会取消；
- 已批准内容修改后，旧批准会失效；
- 日历、列表和看板显示相同的内容；
- 拖动内容看板不能跳过所需审核；
- Slack 按马来西亚时间正确提醒；
- 没批准的内容不会提醒员工发布；
- 点击“已发布”后，系统记录发布人和时间，同时完成对应任务；
- 员工不能进入管理员设置；
- 重要动作都有历史记录；
- Slack 发送失败后可以重试，而且不会重复发送已经成功的消息。

## 15. 第一版不会做什么

- 不会直接连接外部平台自动发布；
- 不会建立每个平台的 API 连接；
- 不会为每个平台保存不同文案；
- 不会使用 BlockNote XL 的 AI、复杂导出和多栏功能；
- 不会让用户选择时区；
- 不会把这个内部工具重新发布成模板库或 UI 组件库。
