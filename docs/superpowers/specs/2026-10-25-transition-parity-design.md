# 转场与原版行为对齐

用户要求消除新版切页卡顿，按 Murmura 的真实转场体验修复。只在隔离分支处理，保持现有数据、权限、双管理员审核、文件和留言流程；不发布。

## 本轮证据
内置浏览器分别操作原版与正式站 Overview→Compose，并保留截图。最终核对发现原版标签仍为 527×917，本机预览为 1280×720，因此这些截图不能用于同尺寸像素差异结论。当前原版入口脚本 SHA-256 与已保存公开脚本一致：96f972529d28af4e99f68c209d272c1f5efa6a0bb7fcca6d4b8e4eb197bb92c6。
原版路由保留导航和各页容器，准备好下一页后旧页 opacity 1→0、y 0→-8，.18 秒 power2.in，再开始新页。标题 .85 秒 power4.out、.022 字符 stagger，面板 .9 秒 power3.out、.07 或 .08 stagger，Compose 面板延迟 .1 秒。原版顶部导航左右边缘分开 .55/.36 秒。
当前 Shell 放在每个页面内；切页没有退场，useEffect 异步 import GSAP 后才 fromTo，存在先画最终状态再隐藏的时序问题。顶部视觉选中也等服务器新页返回。真实权限和数据库查询会增加等待，但尚未测出各项网络耗时，不以猜测代替数据。

## 修复
1. Marketing layout 保留同一 Frame，页头、导航、背景和侧栏跨页持续挂载；已有各页 Shell 在 Frame 内只输出正文，独立渲染仍兼容。
2. 点击立即请求及更新导航视觉选中；服务端等待期间旧正文仍可见。新页就绪时用仅覆盖正文可视区、inert/aria-hidden/去重 ID 的旧画面做 .18 秒退场，避免等待网络时空白。快连点/失败/卸载清理旧画面。
3. 新页 useLayoutEffect 在首次绘制前准备起始状态；共享加载 GSAP，有限超时后直接显示，绝不迟到后再把内容隐藏。新旧动画不叠加到整个表单祖先；Compose 按两个面板分别进入。
4. 保留 reduced-motion、普通浏览器新标签/下载/锚点行为、权限验证和所有原有业务动作。不会把静态假数据当性能优化，也不跨用户缓存认证结果。
5. 测试导航响应、固定 Frame、动画顺序、失败恢复、重复 ID/不可交互快照、最新导航优先、手机；本机预览给用户验收。此轮不宣称整个产品已 1:1。
