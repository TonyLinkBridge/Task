# JUYU 内部帮助中心：设计规格

日期：2026-09-03  
状态：等待用户确认后编写开发计划

## 1. 目标

把目前侧边栏中会打开外部网站的“帮助中心”，改成 JUYU 内部工作台自己的帮助中心。

帮助中心只给已经通过 Clerk 登录和 Slack Workspace 验证的内部成员使用。它不连接 GitBook 官方后台、云端资料、账号系统、AI 或内容管理后台。

页面和文章显示会直接采用用户提供的 `/Users/tony/Downloads/gitbook-main/` 中，与本规格 21 项功能相关的 GitBook 前台代码，并改造成可以读取 JUYU 自己文章资料的版本。

## 2. 明确不做的内容

- 不接入 GitBook 官方账号或登录；
- 不读取 GitBook 云端文章；
- 不加入 GitBook 管理后台；
- 不加入 GitBook AI 问答；
- 不加入 GitBook 广告、访客统计、Cookie 同意和 OpenAPI 功能；
- 不制作新的帮助文章在线编辑后台；
- 不改变现有任务、内容排期、审核和 Slack 通知流程。

## 3. GitBook 代码采用范围

只采用和调整以下 GitBook 前台部分：

- `TableOfContents`：左边文章目录、分组和子目录；
- `PageAside`：右边本页小目录和回到顶部；
- `PageBody`：文章标题、封面、标签、面包屑和上一篇／下一篇；
- `Search`：搜索框、搜索结果和结果高亮；
- `HeaderMobileMenu`：手机版目录菜单；
- `Announcement`：帮助中心公告栏；
- `Footer`：帮助中心页脚；
- `PageFeedback`：文章是否有帮助；
- `PDF`：PDF 阅读、打印和导出；
- `DocumentView`：文章、图片、影片、文件、表格、提示框、代码框、分页标签、数学公式和流程图；
- `ThemeToggler` 相关显示逻辑：与现有工作台深浅模式对接。

这些代码会放进独立的 `features/help-center/gitbook/` 范围，并将 GitBook API、GitBook 账号和 GitBook 云端资料依赖替换成当前项目自己的资料接口。项目会保留来源和授权说明，不删除原项目的版权及授权资料。

项目会新增 `THIRD_PARTY_NOTICES.md` 和对应的 GPLv3 授权文件，列出采用的 GitBook 文件、原始路径和修改日期。帮助中心页脚提供“开源授权”入口，但不使用 GitBook Logo，也不让用户误以为这是 GitBook 官方服务。用户已经选择在内部私人项目中直接采用这些前台代码，并自行负责该使用方式的授权判断。

不会采用以下 GitBook 部分：

- `AI` 和 `AIChat`；
- `AdminToolbar`；
- `Ads`；
- `Cookies`；
- `Insights`；
- `Integrations`；
- `OpenAPI`；
- `SiteAuth` 和 `SiteOAuthConsent`；
- GitBook API、站点发布和云端内容读取逻辑。

## 4. 页面结构

### 帮助中心首页 `/help`

首页显示：

- 公告栏；
- 大型搜索框；
- 文章分类；
- 常用文章；
- 最近更新文章；
- 页脚。

### 文章页面 `/help/[...slug]`

电脑画面采用三栏布局：

1. 左边是文章目录、分组和子目录；
2. 中间是面包屑、封面、标题、标签和文章正文；
3. 右边是这篇文章里面的标题目录和回到顶部。

文章底部显示：

- “这篇文章有帮助吗？”；
- 上一篇；
- 下一篇；
- 页脚。

### 搜索页面 `/help/search?q=关键字`

搜索会检查文章标题、说明、标签和正文。搜索结果显示关键字高亮、所属分类和文章摘要。没有结果时显示清楚的空白提示。

### PDF 页面 `/help/[...slug]/pdf`

提供适合打印和导出 PDF 的文章版本。文章中的图片、表格、提示框、代码和流程图在打印版中保持可读，不显示侧边栏、按钮或工作台导航。

## 5. 手机和平板

- 手机不同时显示三栏；
- 左边文章目录改成顶部“目录”按钮打开的抽屉；
- 右边本页小目录改成“本页内容”折叠区；
- 搜索框占满可用宽度；
- 表格和代码可以横向移动；
- 图片和影片不会超出屏幕；
- 上一篇和下一篇在窄屏幕上下排列；
- 所有按钮和链接保留足够的点击范围。

## 6. 文章资料

第一版文章使用项目里的 Markdown／MDX 文件，不使用 GitBook 云端，也不需要新增 Supabase 文章表。

每篇文章包含：

- 标题；
- 简短说明；
- 分类；
- 子目录位置；
- 显示顺序；
- 封面；
- 标签；
- 最后更新时间；
- 正文。

文章目录由这些资料自动生成。上一篇和下一篇按照目录顺序自动计算。删除或更改文章时，搜索和目录会跟着更新。

第一批内部分类为：

1. 新员工入门；
2. 任务管理；
3. 内容排期；
4. 内容审核；
5. 发布流程；
6. 平台操作；
7. 品牌与文案规范；
8. 常见问题。

第一版会加入示范文章，确保所有内容显示组件都可以实际检查。正式内容可以之后逐篇替换。

## 7. 搜索

帮助中心使用自己的文章搜索资料，不向 GitBook 发送任何内容。

- `/help` 顶部搜索只搜索帮助文章；
- `/help/search` 显示完整搜索结果；
- 工作台现有的全系统搜索会新增“帮助文章”结果类型；
- 输入至少两个字后开始搜索；
- 搜索结果可以用键盘选择；
- 找不到文章时提供返回分类和清除搜索的按钮。

## 8. 文章显示能力

文章必须支持：

- 普通段落、标题和清单；
- 图片和图片说明；
- 外部影片；
- 可下载文件；
- 表格；
- 信息、提醒、警告和危险提示框；
- 有复制按钮的代码框；
- 分页标签；
- 数学公式；
- Mermaid 流程图；
- PDF 文件阅读；
- 当前文章导出为 PDF。

无法播放的影片、打不开的文件或错误的流程图不能让整篇文章坏掉，必须显示白话错误提示。

## 9. 文章反馈

“这篇文章有帮助吗？”提供“有帮助”和“没帮助”。

- 登录成员每篇文章只保留最后一次选择；
- 选择“没帮助”后，可以填写一段简单说明；
- 反馈保存到 Supabase；
- 不发送 Slack 通知；
- 第一版不制作反馈管理页面，管理员可先从 Supabase 查看。

需要新增的资料只保存：文章识别码、用户识别码、选择、说明和时间。不会保存文章全文。

## 10. 登录、权限和安全

- `/help` 所有页面继续由现有 Clerk 登录保护；
- 员工和管理员都可以阅读及提交反馈；
- 未登录用户会走现有登录流程；
- 文章中的 HTML 必须过滤危险内容；
- 外部链接使用安全的新分页设置；
- 文件下载沿用现有的安全下载方式；
- 搜索和反馈接口都要检查登录身份。

## 11. 视觉关系

帮助中心的阅读结构和互动采用选定的 GitBook 前台代码，但外层继续使用 JUYU 工作台：

- 保留现有工作台侧边栏；
- 保留 JUYU、LinkBridge 和 Chiikawa 元素；
- 保留现有头像菜单、通知、私人留言和主题按钮；
- 帮助中心颜色使用现有工作台主题变量；
- 不显示 GitBook Logo、商标或“Powered by GitBook”；
- 不让帮助中心看起来像另外打开的陌生网站。

## 13. 测试标准

自动测试至少覆盖：

- 目录分组和文章顺序；
- 面包屑、上一篇和下一篇；
- 搜索和关键字高亮；
- 手机目录打开和关闭；
- 右边小目录跟随文章标题；
- 深色和浅色模式；
- 反馈新增和修改；
- Markdown／MDX 内容安全；
- 图片、影片、文件和表格；
- 提示框、代码复制和分页标签；
- 数学公式和 Mermaid 流程图；
- PDF 阅读、打印版和导出按钮；
- 未登录用户不能读取帮助文章和提交反馈；
- 员工和管理员都能正常阅读。

浏览器测试至少覆盖电脑和手机两个尺寸，并检查帮助中心不会影响现有首页、任务、内容排期和管理员页面。

## 14. 完成定义

只有在以下条件全部满足时才算完成：

- 21 项验收功能全部能够实际使用；
- 帮助中心链接已经从外部网址改为内部 `/help`；
- GitBook 云端、账号和后台没有被接入；
- 采用的 GitBook 前台代码与来源说明清楚隔离；
- 自动测试、类型检查、代码检查和正式版本构建全部通过；
- 电脑和手机实际检查通过；
- 现有任务、内容排期、审核、通知和 Slack 功能没有被破坏。
